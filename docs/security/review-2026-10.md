# Security review — B7, October 2026

Scope: `apps/api`, `packages/*`, `infra/migrations`, read with an OWASP ASVS L2 lens (auth and
roles, tenancy, webhooks, secrets, SSRF, uploads, exports, rate limits, HTTP hardening and
dependencies). `pnpm audit --prod`: **0 advisories**.

## Findings and dispositions

| ID | Finding | Status |
|---|---|---|
| H1 | SMS-invited members could be taken over by an email sign-up on the `@phone.invalid` placeholder; email invites accepted by unverified addresses | **Fixed.** The placeholder domain is reserved. Invitations are listed and accepted only by a verified phone or email. Email verification added. Regression test reproduces the attack |
| M1 | iCal SSRF guard missed IPv4-mapped/hex, NAT64 and special ranges; DNS-rebinding TOCTOU | **Fixed.** `BlockList` of special-purpose ranges, IPv4-mapped and NAT64 unwrapped, and a pinned lookup that validates every resolved address used for the connection |
| M2 | Rate limits missing on webhooks/callbacks, STK, portal, uploads, exports; no global OTP budget | **Fixed.** Per token and IP on Daraja; per IP on Paystack; STK 3 per 10 min per lease or booking and 5 per hour per phone; uploads, exports and portal tickets per user; OTP verify per IP; forgot-password per IP; 5,000 OTP SMS per day across the platform |
| M3 | Presigned uploads had no size limit | **Fixed.** `Content-Length` is signed (must equal the declared size, ≤ 10 MB). Bucket lifecycle rule for orphaned `org/*` keys is in DEPLOYMENT.md |
| M4 | Idempotency cache stored identity responses (bearer tokens) | **Fixed.** Public identity routes are `idempotency: off`, with a test |
| M5 | No Origin check on cookie-authenticated writes | **Fixed.** Cookie-authenticated non-GET requests from an untrusted Origin/Referer get 403 `origin_not_allowed`; bearer clients are unaffected |
| M6 | Paystack webhook stored unsigned bodies | **Fixed.** Signature checked first; unsigned attempts keep a trace row without the body; rate-limited |
| M7 | Daraja callbacks: disabled channels still processed; STK amount trusted from the callback; IP allowlist optional | **Fixed.** Disabled channels are stored but book nothing; an STK amount that differs from the request is refused; production requires `DARAJA_CALLBACK_IPS` (or an explicit `DARAJA_ALLOW_ANY_CALLBACK_IP=true`). Reverse-proxy logs must redact the callback token path (DEPLOYMENT.md) |
| M8 | SQL and parameters could reach logs and GlitchTip | **Fixed.** Error serializer drops SQL and parameters; secret fields redacted; GlitchTip events carry no request, user or SQL; stored callback outcomes are coarse codes |
| L1 | Staff directory visible to every role | **Fixed.** `GET /v1/members` needs manager |
| L2 | Operator: denied attempts not logged; no second factor | **Fixed** (denied attempts logged). **Deploy control:** `/v1/operator/*` sits behind Cloudflare Access (SSO + MFA) — DEPLOYMENT.md |
| L3 | Dev compose exposes services with default passwords | **Accepted** for dev only. `compose.prod.yml` binds Postgres/Redis to the internal network with generated secrets |
| L4 | CSP disabled | **Fixed.** Strict CSP on API responses; Scalar `/docs` excluded |
| L5 | Credential envelope has no AAD binding to its row | **Deferred** (needs a re-encryption migration and key-rotation tool; tracked for after launch). DB write access is already the trust boundary |
| L6 | Billing applies by `metadata.invoiceId` | **Accepted.** It can only pay someone else's invoice, with Paystack re-verification and an amount check |
| L7 | Phone recycling in the tenant portal | **Accepted with runbook note.** Support archives tenant records when a tenant moves out; portal shows only non-archived records |
| L8 | Tenant role can write `subscription` under RLS | **Accepted.** Only reachable through an injection bug; all writes are service code. Revisit if billing moves to a separate role |

## Checked and fine (summary)
- Default-deny auth modes and `minRole` on mutating routes; last-owner protection.
- Viewer deny-by-default with landlord scope; caretaker property scoping; portal per-lease checks.
- RLS on every tenant table (meta-tested), `security_invoker` views, `SECURITY DEFINER` with a
  fixed `search_path`.
- Every `db.owner` call site is server-driven and never takes an org id from user input.
- Paystack HMAC with `timingSafeEqual` and re-verification; Daraja replay safety (unique provider
  ref, locked STK rows).
- AES-256-GCM envelope encryption; no secret is ever returned.
- Upload key prefix checks; formula-safe CSV; no user-built SQL.
- Password/OTP policy; 1 MB body limit; request timeouts; prototype-poisoning removal; production
  config guards.
